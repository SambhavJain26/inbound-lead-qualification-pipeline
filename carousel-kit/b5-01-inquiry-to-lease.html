The household record

1. Keep
one household reference

Link the inquiry, booking, application and signing record through one reference.

Ambiguous matches need human review, not an AI choice.

Check identity before acting02
The property facts

2. Name the source
of each answer

Use approved property facts for replies.

Name who updates them after policy changes; polished wording doesn't fix outdated information.

Facts need an owner and a current source03
The tour handoff

3. Separate booked
from attended

A calendar confirmation proves

a booking,

not attendance.

Record tour completion separately, with an owner and timestamp, before marking the showing finished.

Demo tour completion is simulated04
The application file

4. Define an
application-ready file

Define the information and documents reviewers need.

Missing evidence needs follow-up; form submission doesn't complete the file or approve the renter.

Application ≠ approval05
The human boundary

5. Separate evidence
from the decision

  • AI extracts sourced facts.
  • Configured rules check criteria.
  • The authorized manager records the rental decision.

Criteria results aren't that person's approval.

The signing event

6. Use confirmation,
not assumption

Keep separate statuses:

Lease
sent.

Lease
signed.

Mark completion only after the signing service confirms the correct application's event.

The waiting work

7. Give waiting work
an owner

For unsigned leases or missing documents, record who acts next and when.

Failed delivery needs an exception, not silent waiting.

The possession boundary

8. Don't collapse
signing into move-in

Keep required funds, unit readiness and authorized access separate from signatures.

Agree applicable conditions with operations; the demo excludes these possession checks.
